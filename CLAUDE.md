# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

DSP-Effects is a growing archive of vintage-DSP-inspired audio effects, built primarily as patches for the [Polyend Endless](https://polyend.com/endless/) pedal via its `FxPatchSDK` (vendored under `sdk/`), with the same DSP code also runnable natively for offline testing and (eventually) as a DAW plugin.

Roadmap, not necessarily sequential — work can interleave across stages and devices:
- **Stage 1**: replicate the core DSP algorithms of the Lexicon PCM81 and Eventide H3000 *functionally* — right topology, right building blocks, working end to end.
- **Stage 2**: refine those implementations closer to the character of the original hardware — tone-matching, nuance, quirks.
- **Stage 3**: expand beyond those two units into new tools and an archive of other great vintage DSP devices.

Algorithms here are documented as **inspired by** the topology/character of the original hardware, never claimed as reverse-engineered or bit-exact clones — the proprietary algorithms aren't public.

`docs/references/` holds primary-source manuals/scans (e.g. the PCM81 User Guide excerpt) so specific claims in `docs/*.md` can be checked directly against them rather than taken on trust.

## Branding & versioning

The repo stays `DSP-Effects`, but the effect line itself is branded **Loom**
(the JUCE plugin's `COMPANY_NAME`/`PRODUCT_NAME`, e.g. "Loom - Lexicon
Hall") — tentative, may evolve. Versioning is repo-wide semver (`project(DSPEffects VERSION x.y.z ...)`
in the top-level `CMakeLists.txt`, pre-1.0 while the archive is young) plus
an independent per-algorithm **Stage 1/2/3** label carried in that
algorithm's `docs/*.md` — the stage label communicates DSP maturity, not
the version number. Bump the repo minor version when an algorithm reaches
Stage 1; patch for fixes/refinement within a stage.

## Architecture

Everything of DSP substance lives in `dsp/` in four tiers — Primitive → Component → Block → Graph — and is shared, unmodified, across three consumers:

- **Primitive** (`dsp/include/dsp/*.h`) — portable, header-only C++20 building blocks with **no heap allocation, no exceptions, no RTTI** (the ARM target is built with `-fno-exceptions -fno-rtti`). Current: `DelayLine` (non-owning, span-based circular buffer), `Allpass` / `ModulatedAllpass` (Schroeder diffusers; `Allpass` also has an opt-in `setDelaySamples()` for callers whose own delay-per-stage is a runtime parameter rather than fixed by buffer capacity — the H3000's Ultra-Tap), `Comb` (feedback comb / recirculating echo, continuously-settable delay length), `Crossover` (one-pole two-band splitter, low+high reconstruct the input exactly), `OnePoleLowpass` (damping/high-cut), `StereoRotate.h`'s `rotateStereoWidth` (continuously-variable mid/side stereo imaging), `Decay.h`'s `rt60ToGain` (per-line feedback gain for a target RT60), `Envelope.h`'s `LinearRamp` (one-shot ramp; used for Attack/Shape-Spread shaping and for muting output while a structural parameter like reverb Size changes), `GlideParameter` (a scalar that glides to a new target within a settable range/response, or jumps instantly beyond it — the PCM81's GldResp/GldRange), `LFO` (sine/triangle plus `nextRandomWalk()`, a smoothly-wandering random modulation source for sweep generators that are explicitly *not* sine/triangle, like the H3000's Swept Combs), `FeedbackMatrix.h`'s Householder mixing matrix for FDNs, `PitchShifter` (delay-line/grain-based real-time pitch shifter, the building block behind Eventide H3000-style effects), `PitchDetector` (autocorrelation-based real-time monophonic pitch tracker), `ReverseBuffer` (a "tape reverse" splice generator: records a settable-length segment while playing back the previous one time-reversed, ping-ponging between two fixed halves so a stable region is always available to read backward through), `StutterCapture` (the H3000 Stutter's own "Stutter Control" block: continuously records its input, and on trigger freezes recording and loops the most recently captured window exactly, repeated a settable number of times, before resuming live passthrough), `NoiseGenerator` (deterministic xorshift32 white noise, the H3000 Patch Factory's "Noise Gen" block), `StateVariableFilter` (a Chamberlin SVF producing lowpass/highpass/bandpass simultaneously from one cutoff+Q pair, including genuine self-oscillation at Q=1 kept numerically bounded — Patch Factory's "tuneable filter" blocks), and `DiatonicScale.h`'s `diatonicSemitones`/`nearestScaleDegreeIndex`/`HarmonicInterval` (turning a tracked pitch plus a chosen interval into an absolute semitone shift, per-note-correct rather than a fixed transposition). The PCM81 ones map directly onto that manual's block diagrams — see `docs/lexicon-pcm81-reference.md`; the H3000 ones are grounded in `docs/eventide-h3000-notes.md`.
- **Component** (`dsp/include/dsp/*.h`) — a small reusable sub-assembly of a few Primitives, not a full effect on its own: `DiffuserChain<N>` (N Allpasses sharing one Diffusion amount), `Voice` (a `Comb` + level + pan — the repeated unit behind the PCM81's multi-voice sections), `PitchShiftVoice` (a `Delay` feeding a `PitchShifter`, one input in/one shifted output out, with a direct semitone/cents shift amount rather than pitch-tracked — the repeated unit behind the H3000's fixed-interval pitch-shift algorithms: Layered/Dual/Stereo Shift today, Multi-Shift to come), and `SweptCombVoice` (a `Comb` whose delay length wanders continuously via `LFO::nextRandomWalk()`, plus level and pan — the repeated unit behind the H3000's Swept Combs, and intended for reuse by Swept Reverb/Reverb Factory). Same directory as Primitives; the distinction is "composes other primitives" vs. "is one."
- **Block** (`dsp/include/dsp/algorithms/*.h`) — a reverb/effect core built from Primitives/Components, independent of any SDK. Exposes `prepare(sampleRate, workingBuffer)`, per-parameter setters, `process(left, right)` (whole-block) and/or `processSample(float&, float&)` (single-sample step, so a Graph can interleave it with other per-sample Components), and `reset()`. The PCM81's five reverb cores (Concert Hall, Plate, Chamber, Inverse, Infinite) share one signal path per the manual, so `ReverbCore.h` implements that shared path once (Diffusion/PreDelay/8-line Householder FDN tank/early reflections/Definition/Depth/Rvb In-Out/freeze) and each concrete core derives from it, adding only its own documented control(s) via protected hooks: `applyPreEcho()` for Plate/Chamber/Infinite's recirculating EkoDly/EkoFbk pre-echo, `effectiveDiffusion()` for dynamic diffusion shaping like Plate's Attack, `outputEnvelope()`/`shapeWetOutput()` for shaping the wet output over time (Chamber/Infinite's Shape+Spread swell via the `outputEnvelope()` scalar; Inverse's independent Low Slope/Mid Slope via overriding `shapeWetOutput()` directly, since it needs to band-split rather than just scale). `ConcertHall.h` is the reference core (no additions); `Plate.h` adds Attack + pre-echo; `Chamber.h` adds Shape+Spread + pre-echo; `Infinite.h` is Chamber + different defaults (freeze already lived on the base); `Inverse.h` replaces RT60 decay entirely with Duration+Slopes, deliberately *not* touching the recirculating feedback gain (a rising envelope needs the tank to keep sustaining so there's something to reveal - see `docs/lexicon-pcm81-inverse.md` for the bug this caught). The first Eventide H3000-family Block, `DiatonicShift.h`, is unrelated to `ReverbCore` (different device, different topology entirely): mono-sums the stereo input through one shared `Delay` and one shared `PitchDetector`, driving two independent `PitchShifter`-based Voice generators (Left, Right) from the tracked note — matching the real Algorithm 100's "the H3000 tracks your pitch and plays the correct notes" mechanism, not a fixed transposition — with each Voice's output regenerating back into the shared input for cascading harmony. See `docs/eventide-diatonic-shift.md`, including the history of why an earlier fixed-transposition version had to be rebuilt. `LayeredShift.h` (Algorithm 101) is the second H3000 Block: two `PitchShiftVoice` Components, both fed from the left input alone (per that algorithm's own manual page — not a stereo sum, unlike Diatonic Shift), each with its own Delay/cents/Feedback and no pitch tracking at all — a direct, fixed-interval shift rather than a diatonically-correct one. See `docs/eventide-layered-shift.md`. `DualShift.h` (Algorithm 102) reuses `PitchShiftVoice` unchanged for an even simpler topology: two fully independent per-channel voices with no shared input or feedback point at all ("completely separate pitch shifters" per the manual). See `docs/eventide-dual-shift.md`. `StereoShift.h` (Algorithm 103) sits between the two: independent per-channel signal paths like Dual Shift, but one shared Coarse/Fine/Delay/Feedback/Mix value drives both, matching the manual's "parameters of both channels adjust together." See `docs/eventide-stereo-shift.md`. `ReverseShift.h` (Algorithm 104) is the first Eventide Block since Diatonic Shift to need a genuinely new primitive rather than reusing `PitchShiftVoice`: mono-sums the input through two independent `ReverseBuffer -> PitchShifter` chains (own splice Length, own pitch-shift cents), since true time-reversal is mechanistically unlike the smooth continuous shifting the other Shift algorithms share. See `docs/eventide-reverse-shift.md`. `SweptCombs.h` (Algorithm 105) starts a different H3000 family entirely (no pitch shifting): six `SweptCombVoice`s, each with its own base Delay/Rate/Depth/Feedback/Pan/Level, summed into a stereo mix, with five Master controls proportionally scaling all six lines' values at once without altering the underlying per-line settings. See `docs/eventide-swept-combs.md`. `SweptReverb.h` (Algorithm 106) shares that six-swept-line shape but feeds the lines into a Householder-mixed feedback network (reusing `householderMix()` from the PCM81 side's own tank - the first Primitive shared across both device families here) instead of a stereo mixer, turning six discrete sweeping echoes into a continuous reverb tail. See `docs/eventide-swept-reverb.md`. `ReverbFactory.h` (Algorithm 107), the last of the "six delay lines" family, uses *fixed* (non-swept) lines and adds a dynamics Gate that crossfades each line's decay gain and tone between independent "On"/"Off" settings, reusing `rt60ToGain()` and `Crossover` from the PCM81 side for the first time in the Eventide family. See `docs/eventide-reverb-factory.md`. `UltraTap.h` (Algorithm 108) reuses `DiffuserChain<4>` from the PCM81 side for a 4-stage Allpass diffusor feeding a new 12-tap *cumulative* delay line (each tap's own Delay is the time since the previous tap, not from the input) with independent Level/Pan per tap and one selectable feedback tap; building this caught a real bug where `Allpass`'s delay length wasn't actually runtime-settable, fixed with an opt-in extension that doesn't disturb existing callers. See `docs/eventide-ultra-tap.md`. `LongDigiplex.h` (Algorithm 109) is the simplest H3000 Block yet: a single `DelayLine` with feedback and `GlideParameter`-smoothed delay changes, reusing both primitives from the PCM81 side unchanged. See `docs/eventide-long-digiplex.md`. `DualDigiplex.h` (Algorithm 110) is the independent-two-channel sequel: two hand-rolled copies of that same Delay+Feedback+Glide shape (not a composition of two `LongDigiplex` instances, since that Block's Left-In-only/dual-output behavior is hard-coded rather than a setting), sharing one Repeat flag and a Stereo/Mono input-routing flag. See `docs/eventide-dual-digiplex.md`. `PatchFactory.h` (Algorithm 111) is a genuine modular patch-bay rather than a fixed topology: two tuneable `StateVariableFilter`s, two `DelayLine`s, one `PitchShifter`, two scalers, two summing junctions, and a `NoiseGenerator`, wired by a settable 16-source x 13-destination patch matrix (`setPatch(Destination, Source)`) matching the manual's own Patch destinations/Patch Sources tables exactly — every cross-connection reads the previous sample's value of its source, making the matrix inherently acyclic for any user-chosen patch without needing to detect cycles. See `docs/eventide-patch-factory.md`. `Stutter.h` (Algorithm 112) pairs a per-channel `PitchShifter`+`DelayLine` chain with a `StutterCapture` (the manual's own "Stutter Control" block) and two independent sweep generators; rather than building a *second* full patch matrix for the manual's own 4-trigger-key routing system (Patch Factory already built one general one), it exposes a fixed set of eight trigger methods directly (two stutter presets, two sweep generators' up/down/random-pitch actions) plus an Auto sequencer. See `docs/eventide-stutter.md`. `Timesqueeze.h` (Algorithm 113) reuses `PitchShifter` unchanged for two independent per-channel shifters sharing one computed ratio: Time% (the length change a connected tape machine would be told to make - out of scope, no equivalent hardware exists here) implies a speed ratio, and both channels are shifted by its inverse (compensating for the pitch change that speed change would otherwise cause) times an independent Pitch trim - the audio-domain half of an algorithm whose manual page is otherwise almost entirely about physical tape-machine remote control. See `docs/eventide-timesqueeze.md`. `DenseRoom.h` (Algorithm 114) is a genuine named evolution of `ReverbFactory`'s own 6-line Householder-tank family per its own manual page ("much improved early response... over the original 'Reverb Factory' program"): reuses `rt60ToGain()`, `OnePoleLowpass`, and `householderMix()` directly from Reverb Factory, adds a `DiffuserChain<3>` diffusion stage and explicit per-line Pan/Level (unlike Reverb Factory's fixed alternating panning), and drops the Gate for a single Rev Time; building it caught a real bug where the diffusion stages were left at their fixed buffer-capacity delay (~240ms) instead of short values, making the diffuser act as its own slow secondary reverb independent of Rev Time — fixed via the same opt-in `setDelaySamples()` extension built for Ultra-Tap. See `docs/eventide-dense-room.md`. `Vocoder.h` (Algorithm 115) is a classic 12-band channel vocoder built from primitives already in the archive: a `StateVariableFilter` bandpass bank analyzes the voice (Right) input's per-band energy through two cascaded `OnePoleLowpass` smoothing stages (Formant Speed then Envelope Speed), driving an identically-shaped synthesis filterbank processing the instrument (Left) input — the manual's own "Min Error"/"Max Resonance" language reads more like an adaptive/LPC-style filter, but that isn't public, so this documents the gap rather than guessing. The first algorithm in this archive where Left/Right are channel-specific rather than interchangeable (Left = synthesis, Right = analysis, per the manual). See `docs/eventide-vocoder.md`. `MultiShift.h` (Algorithm 116) reuses `DelayLine`/`PitchShifter`/`ReverseBuffer`/`rotateStereoWidth` unchanged for a genuine escalation over Dual Shift: two independent pitch-shift channels (each a Delay→Shift chain, or a Reverse-splice→Shift chain in Reverse mode - reusing Reverse Shift's own mechanism directly, per the manual's "exactly like program 104") plus two independent dry delay taps (four sources total), each pitch shifter's own input additionally patchable from any two of the four sources via the same one-sample-latency technique Patch Factory's own matrix uses, just narrower in scope. See `docs/eventide-multi-shift.md`. `BandDelay.h` (Algorithm 117) takes the manual's own singular phrasing ("a multi-tap delay line," not "eight delay lines") literally: one shared `DelayLine` with 8 independently-settable read taps, each feeding its own `StateVariableFilter` (reused a third time, after Patch Factory and Vocoder), output Level, and Pan, plus one recirculating feedback loop. Skips the manual's MIDI-driven filter-tuning Note Mode entirely, since no MIDI input pathway exists anywhere in this project — every `PluginProcessor::acceptsMidi()` in this archive returns `false` — replacing its Note parameter with a direct settable base Hz per filter instead. See `docs/eventide-band-delay.md`. `StringModeller.h` (Algorithm 118) needed a genuinely new Component, `StringVoice` (a Karplus-Strong string: `DelayLine` + damping `OnePoleLowpass` + a small DC-blocking stage), for six string resonators excited by a shared `StateVariableFilter`+`NoiseGenerator` stimulation signal (reused a fourth time) and/or the live input, feeding an `LFO`-modulated Chorus; since no MIDI input pathway exists in this project, the manual's Gate Mode is always effectively "Open" (continuous stimulation, the only mode that produces sound without MIDI note-on events) and a `trigger()` method substitutes a manual "pluck" for the missing keyboard — building this caught a real bug where a plain one-pole lowpass's unity gain at DC let a plucked string's residual DC bias outlive its own pitch at low `Bright` settings. See `docs/eventide-string-modeller.md`. `Phaser.h` (Algorithm 119) needed a genuinely new Primitive, `AllpassFilter` (a first-order allpass *filter* - unity gain everywhere, a swept -90-degree corner frequency - not the fixed-delay Schroeder `Allpass` used for reverb diffusion elsewhere in this archive despite the shared name): twelve stages in series, swept by an LFO/envelope-follower/ADSR, mixed back with dry asymmetrically per the manual's own diagram (left = dry+wet, right = wet only). The ADSR mode's own Attack/Release Thresholds let it auto-cycle purely from the envelope follower, so it works fully without MIDI; `trigger()` substitutes a manual gesture for the manual's MIDI-only ADSR Trigger. See `docs/eventide-phaser.md`.
- **Graph** (`dsp/include/dsp/graphs/*.h`) — a full algorithm as the user experiences it: one Block wrapped in its class-specific front end (e.g. `ConcertHallAlgorithm.h` = the Concert Hall Block + the PCM81's 4-Voice "Reverb Shell": 4 `Voice` Components + post-delay + FX Mix/Width/Hi-Cut/Adjust; `DiatonicShiftAlgorithm.h` = the DiatonicShift Block + input level trim, no generic stereo-width control since the real algorithm's stereo image comes from two independently-harmonizing Voice generators rather than a stereo pair being rotated after the fact — see that file's doc comment; `LayeredShiftAlgorithm.h` = the LayeredShift Block + input trim on the one channel it reads, same width reasoning; `DualShiftAlgorithm.h` = the DualShift Block + independent Left/Right input trim; `StereoShiftAlgorithm.h` = the StereoShift Block + independent Left/Right input trim; `ReverseShiftAlgorithm.h` = the ReverseShift Block + input trim; `SweptCombsAlgorithm.h` = the SweptCombs Block + input trim; `SweptReverbAlgorithm.h` = the SweptReverb Block + input trim; `ReverbFactoryAlgorithm.h` = the ReverbFactory Block + input trim; `UltraTapAlgorithm.h` = the UltraTap Block + input trim; `LongDigiplexAlgorithm.h` = the LongDigiplex Block + input trim; `DualDigiplexAlgorithm.h` = the DualDigiplex Block + independent Left/Right input trim; `PatchFactoryAlgorithm.h` = the PatchFactory Block + input trim; `StutterAlgorithm.h` = the Stutter Block + independent Left/Right input trim; `TimesqueezeAlgorithm.h` = the Timesqueeze Block + independent Left/Right input trim, no Mix control; `DenseRoomAlgorithm.h` = the DenseRoom Block + input trim; `VocoderAlgorithm.h` = the Vocoder Block + independent Left/Right input trim; `MultiShiftAlgorithm.h` = the MultiShift Block + independent Left/Right input trim; `BandDelayAlgorithm.h` = the BandDelay Block + independent Left/Right input trim; `StringModellerAlgorithm.h` = the StringModeller Block + input trim; `PhaserAlgorithm.h` = the Phaser Block + independent Left/Right input trim). Patches and plugins wire up the Graph, not the bare Block.
- `patches/<device>/<algo>/` — thin Polyend `Patch` adapters (e.g. `patches/lexicon/hall/PatchImpl.cpp`, `patches/eventide/diatonic_shift/PatchImpl.cpp`, `patches/eventide/layered_shift/PatchImpl.cpp`, `patches/eventide/dual_shift/PatchImpl.cpp`, `patches/eventide/stereo_shift/PatchImpl.cpp`, `patches/eventide/reverse_shift/PatchImpl.cpp`, `patches/eventide/swept_combs/PatchImpl.cpp`, `patches/eventide/swept_reverb/PatchImpl.cpp`, `patches/eventide/reverb_factory/PatchImpl.cpp`, `patches/eventide/ultra_tap/PatchImpl.cpp`, `patches/eventide/long_digiplex/PatchImpl.cpp`, `patches/eventide/dual_digiplex/PatchImpl.cpp`, `patches/eventide/patch_factory/PatchImpl.cpp`, `patches/eventide/stutter/PatchImpl.cpp`, `patches/eventide/timesqueeze/PatchImpl.cpp`, `patches/eventide/dense_room/PatchImpl.cpp`, `patches/eventide/vocoder/PatchImpl.cpp`, `patches/eventide/multi_shift/PatchImpl.cpp`, `patches/eventide/band_delay/PatchImpl.cpp`, `patches/eventide/string_modeller/PatchImpl.cpp`, `patches/eventide/phaser/PatchImpl.cpp`) that own one Graph, map its parameters to the pedal's 3 knobs (`endless::ParamId::kParamLeft/Mid/Right`) and 2 footswitch actions (`kLeftFootSwitchPress/Hold`), and report LED color via `Patch::Color`. Each has its own tiny `Makefile` that just sets `PATCH_NAME`/`PATCH_SOURCES`/`EXTRA_INCLUDES` and includes `sdk/Patch.mk`.
- `sdk/` — vendored upstream `FxPatchSDK` (`source/Patch.h` interface, `internal/` ABI glue and linker script) plus `sdk/Patch.mk`, the shared cross-compile Makefile logic every patch includes. Treat `internal/` as upstream boilerplate; don't hand-edit it.
- `host/` — native (host-arch) CMake target `dsp_host_render` that instantiates an engine directly (no SDK involved), renders an impulse response and a test-tone burst to WAV in `--out=<dir>` (default `out/`), and prints an RT60-style decay curve. This is the fast iteration loop before touching real hardware.
- `plugin/` — JUCE-based VST3/AU/Standalone wrapper ("Loom", CMake `FetchContent`d JUCE 8.0.14) around the same engines, for testing in Ableton/Bitwig/standalone. Gated behind the `DSP_EFFECTS_BUILD_PLUGIN` CMake option so a normal build doesn't fetch JUCE. One `juce_add_plugin` target per algorithm (currently `LexiconHallPlugin`, `LexiconPlatePlugin`, `LexiconChamberPlugin`, `LexiconInfinitePlugin`, `LexiconInversePlugin`, `EventideDiatonicShiftPlugin`, `EventideLayeredShiftPlugin`, `EventideDualShiftPlugin`, `EventideStereoShiftPlugin`, `EventideReverseShiftPlugin`, `EventideSweptCombsPlugin`, `EventideSweptReverbPlugin`, `EventideReverbFactoryPlugin`, `EventideUltraTapPlugin`, `EventideLongDigiplexPlugin`, `EventideDualDigiplexPlugin`, `EventidePatchFactoryPlugin`, `EventideStutterPlugin`, `EventideTimesqueezePlugin`, `EventideDenseRoomPlugin`, `EventideVocoderPlugin`, `EventideMultiShiftPlugin`, `EventideBandDelayPlugin`, `EventideStringModellerPlugin`, `EventidePhaserPlugin`), each with its own `PluginProcessor` in `plugin/source/`. Every plugin's `createEditor()` returns the shared `LoomPluginEditor` (`plugin/source/LoomPluginEditor.*`): the full generic parameter list plus a "Show Architecture" button that swaps in `ArchitectureView` (`plugin/source/ArchitectureView.*`), a signal-flow diagram driven entirely by that algorithm's `dsp::schema::AlgorithmSchema` (`dsp/include/dsp/schema/`), with clickable stages (e.g. the Tank, Diffusion) drilling into a nested sub-diagram of that stage's internals — see `docs/algorithm-schema-notes.md`.

Because a `Patch`'s delay lines must live in the pedal's external working buffer (`Patch::kWorkingBufferSize` = 2,400,000 floats, `Patch::kSampleRate` = 48000) rather than internal RAM, every Block/Graph's `prepare()` takes a `std::span<float>` and carves it up itself (see `ConcertHallAlgorithm::requiredWorkingBufferSize()` / `subspan` usage, which sums its own needs plus its owned Block's `requiredWorkingBufferSize()`) — don't give primitives owned storage.

**Future direction (not yet built):** today's `plugin/` is one `juce_add_plugin` target per algorithm. The intent is to eventually also have a single, higher-level "Loom" plugin that can browse/select from the full list of algorithms across all devices and generically visualize whatever parameters the selected engine exposes, rather than requiring a separate plugin per algorithm. Likely needs each engine to expose its parameter set in some introspectable/self-describing form (name, range, current value) rather than only bespoke setters, so a generic UI can be built over any engine without per-algorithm UI code. See `docs/algorithm-schema-notes.md` for a related idea: a declarative per-algorithm schema (topology + parameters) that could drive that generic UI, auto-rendered docs/diagrams, and give AI tooling a structured artifact to reason about algorithms across devices — not yet designed; worth revisiting once a few more algorithms exist.

## Commands

Native host harness (primary day-to-day build/test loop):
```
cmake -S . -B build
cmake --build build -j
./build/host/dsp_host_render concert_hall --out=out
```
Exit code is non-zero if any rendered buffer contains a non-finite sample or a WAV fails to write; the decay curve it prints is the quickest sanity check that an engine's RT60/damping behaves.

Quick single-header smoke test without CMake, e.g. while iterating on a new `dsp/` primitive or engine:
```
g++ -std=c++20 -Wall -Wextra -I dsp/include <file>.cpp -o /tmp/smoketest && /tmp/smoketest
```

Cross-compiling an individual patch for the Endless (requires the [GNU Arm Embedded Toolchain](https://developer.arm.com/Tools%20and%20Software/GNU%20Toolchain); not available in this sandbox):
```
cd patches/lexicon/hall
make TOOLCHAIN=/usr/bin/arm-none-eabi-
```
Produces `build/<PATCH_NAME>_<timestamp>.endl` — copy that file to the Endless's USB drive to deploy. `make -n` from a patch directory is useful to sanity-check the build graph without a toolchain installed.

Plugin build (fetches JUCE 8.0.14 on first configure; needs `libx11-dev`, `libxrandr-dev`, `libxinerama-dev`, `libxcursor-dev`, `libxcomposite-dev`, `libxi-dev`, `libasound2-dev`, `libfreetype-dev` on Linux):
```
cmake -S . -B build-plugin -DDSP_EFFECTS_BUILD_PLUGIN=ON -DCMAKE_BUILD_TYPE=Release
cmake --build build-plugin -j -t LexiconHallPlugin_VST3
```
Produces a `.vst3` under `build-plugin/plugin/LexiconHallPlugin_artefacts/Release/VST3/`.
